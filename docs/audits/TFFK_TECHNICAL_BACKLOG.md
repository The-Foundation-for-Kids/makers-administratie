## Priority guide

- **P0:** Resolve or bound authorization risk before broad maintenance or access expansion.
- **P1:** Address invitation integrity, deployment safeguards, import correctness and baseline regression coverage.
- **P2:** Clarify business/data ownership and improve integrity/operations after production state is understood.
- **P3:** Improve maintainability and documentation.

## Evidence confidence and dependencies

- Code locations above are verified by static inspection of the checked out `main` tree. Whether a given control is reachable in production depends on deployed code, role/permission data and Filament behavior.
- Branch comparison uses the local `origin/*` refs available at audit time; they were not refreshed from the network.
- WordPress findings are limited to this Laravel repository. The separate installation must be inspected to classify integration status.
- Package constraints and lock versions are verified from Composer files; no dependency compatibility matrix or security advisory scan was run. Upgrade planning should use current upstream support/advisory information and the deployed PHP/runtime details.
